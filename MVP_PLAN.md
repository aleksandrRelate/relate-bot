# Relate Portal — план MVP (шаг 1)

## Что входит в MVP
Одно Next.js-приложение, два представления:
- **/admin** — вход команды (magic link), список проектов, карточка проекта: паспорт, файлы, ссылка на бриф, публикация.
- **/p/[slug]** — клиентский портал: Brand, Web, библиотека ассетов, «Для вашего ИИ» (скачать context.md). Product/Motion — заглушки «Можно добавить».

Проект = строка в таблице `projects` + папка `projects/<id>/` в Storage. Новый проект — кнопка, без нового репо/деплоя (это и есть проверка переиспользуемости).

Этого достаточно для ближайшего проекта: команда собирает материалы, клиент видит только опубликованное и скачивает контекст для своего агента.

## Схема данных (Supabase)
| Таблица | Поля |
|---|---|
| projects | id, slug, name, client, status, owner, theme (json: цвета/лого), sections (brand/web/…), brief_url, brief_id, brief_version |
| passport | project_id, field, value, source (`brief`/`manual`), approved, client_visible |
| items | project_id, section, kind (file/link/guide/prototype), title, storage_path/url, published |
| members | project_id, user_id, role (`team`/`client`) |

Права — RLS по `members` на таблицах и на Storage (не просто project_id). Файлы отдаются только через подписанные ссылки. Отзыв доступа = удалить строку в `members`.

## Бриф
MVP: кнопка «Открыть инструмент брифов» + поле ссылки/ID + импорт ответов (JSON/CSV/вставка текста) → поля паспорта с `source=brief`.
Повторный импорт того же `brief_id+version` — не дублирует; поля с `approved=true` не перезаписываются. ИИ-заполнение — после пилота.

## Отложено и обходной путь
| Отложено | Временно |
|---|---|
| MCP для клиента | Экспорт `context.md` (клиентские поля паспорта + опубликованные материалы + инструкция). Это **не** MCP. |
| Запись контента агентом | Скрипт `scripts/import.ts` по service key только у команды → создаёт черновики, публикует человек. |
| API/SSO с брифами | Ссылка + ручной импорт. |
| Роли сложнее team/client, история правок | Supabase backups + `updated_at`. |

## Стек и совместная работа
- GitHub (орг Relate) → ветка на задачу → PR → Vercel Preview → ревью → merge в `main` = прод.
- Next.js + TypeScript, Supabase (DB/Auth/Storage), Vercel.
- Preview использует отдельный Supabase-проект с тестовыми данными; миграции — `supabase/migrations`, применяются только через merge.
- Конфликты: защищённая `main`, merge только через PR, обязательное обновление ветки от актуального `main`.
- Второй участник: приглашение в GitHub-орг + Vercel team + `.env.local` с тестовым Supabase → `AGENTS.md` объясняет остальное агенту. Личные аккаунты, без общих.

## Что нужно от коллег
1. URL/код/формат экспорта инструмента брифов.
2. Доступ в GitHub-орг, Vercel team и Supabase org Relate (владелец — Relate, не разработчик).
3. Материалы ближайшего проекта и что из них можно показывать клиенту.
4. Кто второй участник для проверки процесса.

## Первая демонстрация
Создать проект → привязать бриф и импортировать ответы → поправить и утвердить паспорт → загрузить логотип в Brand и прототип-ссылку в Web → опубликовать → открыть клиентом, скачать ассет и context.md → показать, что второй проект и неопубликованное недоступны. Затем PR второго участника с превью.
